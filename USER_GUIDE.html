۱. iMat چیست و برای چه کسانی ساخته شده؟

iMat Warehouse یک نرم‌افزار دسکتاپ تخصصی برای مدیریت موجودی و اسناد انبار در پروژه‌های EPC (مهندسی، تأمین و اجرا) است. برخلاف نرم‌افزارهای عمومی انبارداری، از همان ابتدا برای اسناد واقعی پروژه‌های صنعتی طراحی شده:

  • MRR – گزارش دریافت مواد
  • MIV – حواله خروج مواد
  • MTR – انتقال بین انبارها
  • OS&D – گزارش Excess / Shortage / Damage
  • QC Release، Preservation و ردیابی شماره ذوب (Heat No)

این نرم‌افزار هم می‌تواند کاملاً آفلاین روی یک لپ‌تاپ کار کند و هم در محیط شبکه با SQL Server به صورت چندکاربره استفاده شود.

تیم‌های کنترل مواد و انبار پروژه‌های نفت و گاز معمولاً با پراکندگی داده‌ها، اکسل‌های موازی و ریسک اشتباه در موجودی مواجه‌اند. iMat دقیقاً برای کاهش همین دردسرها ساخته شده است.

۲. نصب و راه‌اندازی

پیش‌نیازها

  • ویندوز ۱۰/۱۱ (یا لینوکس / مک)
  • پایتون ۳.۹ یا بالاتر
  • حدود ۵۰۰ مگابایت فضای آزاد

نصب از سورس

git clone https://github.com/Tahmoures54/MaterialAgent.git
cd MaterialAgent
python -m venv venv

# ویندوز:
venv\Scripts\activate

# لینوکس / مک:
source venv/bin/activate

pip install -r requirements.txt
python main.py
نکته: برای استفاده از SQL Server بعداً کافی است pyodbc و درایور ODBC مایکروسافت را نصب کنید. جزئیات در بخش دیتابیس آمده است.

۳. شروع کار — جریان اصلی اسناد

جریان استاندارد در iMat بسیار شبیه فرآیند واقعی انبار پروژه‌های EPC است:

MRR (دریافت) ← QC Release ← MIV (صدور)
  1. کالاها را در Material Master تعریف کنید.
  2. مکان‌های انبار (Warehouse → Rack → Bin) را بسازید.
  3. با سند MRR مواد را وارد قرنطینه کنید.
  4. با QC Release وضعیت را به Accepted یا Rejected تغییر دهید.
  5. با سند MIV مواد پذیرفته‌شده را صادر کنید.
امنیت موجودی: اگر یک سند پیش‌نویس (Draft) را حذف کنید، iMat به‌طور خودکار موجودی پست‌شده را برمی‌گرداند تا موجودی «باد» نکند. این یکی از نقاط قوت نرم‌افزار نسبت به بسیاری از سیستم‌های ساده‌تر است.

۴. انتخاب دیتابیس: SQLite یا SQL Server

از نسخه ۲.۲ به بعد می‌توانید بین دو موتور دیتابیس جابه‌جا شوید. تنظیمات در فایل app_config.json قرار دارد.

حالت مناسب برای توضیح
SQLite (پیش‌فرض) تک‌کاربره، آفلاین، لپ‌تاپ سایت بدون نصب سرور، سریع و قابل حمل
SQL Server چندکاربره تحت شبکه اتصال به سرور مرکزی سازمان

فعال‌سازی SQL Server

  1. درایور ODBC Driver 17 (یا ۱۸) مایکروسافت را نصب کنید.
  2. دستور زیر را اجرا کنید: 
    pip install pyodbc
  3. در app_config.json بخش دیتابیس را به این شکل تنظیم کنید:
"database": {
  "engine": "sqlserver",
  "sqlserver": {
    "enabled": true,
    "driver": "ODBC Driver 17 for SQL Server",
    "server": "YOUR_SERVER",
    "port": 1433,
    "database": "iMat",
    "username": "imat_user",
    "password": "********",
    "trusted_connection": false,
    "encrypt": true,
    "trust_server_certificate": true
  }
}
توجه: بک‌آپ فایل‌بیس فقط در حالت SQLite در دسترس است. برای SQL Server از ابزارهای استاندارد پشتیبان‌گیری خود سرور استفاده کنید.
همین انعطاف‌پذیری — کار کردن هم روی لپ‌تاپ سایت بدون اینترنت و هم روی سرور مرکزی سازمان — یکی از دلایلی است که iMat برای پروژه‌های EPC طراحی شده است.

۵. قابلیت‌های هوشمند (پیش‌بینی و دستیار)

بخش هوش مصنوعی iMat کاملاً آفلاین کار می‌کند و نیازی به اینترنت یا کلید API ندارد.

پیش‌بینی تقاضا

  • چند روش کلاسیک: میانگین متحرک، هموارسازی نمایی، رگرسیون، Holt-Winters
  • روش مخصوص تقاضای پراکنده (Intermittent)
  • Ensemble: میانگین بهترین روش‌ها برای پیش‌بینی پایدارتر
  • تشخیص خودکار اینکه تقاضا منظم است یا پراکنده

بهینه‌سازی موجودی

  • محاسبه EOQ (مقدار سفارش اقتصادی)
  • Safety Stock و نقطه سفارش (Reorder Point)
  • طبقه‌بندی ABC

دستیار پرسش و پاسخ

می‌توانید به فارسی یا انگلیسی سوال بپرسید؛ مثلاً:

  • «موجودی کالای X چقدر است؟»
  • «اقلام کم‌موجودی را نشان بده»
  • «خلاصه وضعیت انبار»
  • «تراکنش‌های ۷ روز اخیر»
هدف این بخش جایگزین کردن مدل‌های سنگین ابری نیست؛ بلکه دادن بینش سریع و قابل اتکا به مسئول انبار است — دقیقاً همان چیزی که در شرایط واقعی پروژه نیاز دارید.

۶. نقش‌های کاربری

نقش دسترسی اصلی
Admin دسترسی کامل، مدیریت کاربران و لایسنس
Operator ایجاد و ویرایش اسناد انبار و حرکات موجودی
Technical Office درخواست مواد (MR)، MSR، ارجاع ISO/WBS
QC Inspector QC Release، Preservation، ثبت بازرسی
Viewer فقط مشاهده گزارش‌ها و موجودی

۷. نکات کاربردی و عیب‌یابی

  • قبل از کار جدی، یک بار مسیر MRR → QC → MIV را با داده آزمایشی طی کنید.
  • اگر سند Draft را حذف کردید و موجودی برنگشت، نسخه نرم‌افزار را بررسی کنید (از ۲.۰ به بعد این رفتار سخت‌گیرانه‌تر شده).
  • برای تغییر موتور دیتابیس، برنامه را کاملاً ببندید و دوباره باز کنید.
  • لاگ‌ها در پوشه logs ذخیره می‌شوند؛ در صورت خطا آن‌ها را بررسی کنید.
  • تست‌ها را می‌توانید با دستور زیر اجرا کنید: 
    python -m pytest tests -q
